# 家庭网络 — 路由器登录与测速

记录家里网络的设备、两个脚本的用法，以及路由器读到的状态。排查慢/掉线时直接照这里来，不用每次重新摸登录方式。

## 拓扑

```
电信光纤 → 华为 HN8156XR-10 FTTR 主光猫 (192.168.1.1, PPPoE 拨号)
            → 光纤 → FTTR 从机 (HR8125XN, 带 2.5G 网口)
                      → 2.5G 网线 → TP-LINK TL-R5009PE-AC 路由器 (WAN=192.168.1.2, LAN=192.168.0.1)
                                     → 一楼/三楼 AP (TL-7AP5100HC, Wi-Fi 7)
```

- 宽带 2000M。
- **双重 NAT**：光猫拨号后给路由器 WAN 发 DHCP(192.168.1.2)，路由器再做一层 NAT。所有内网流量都过这台路由器。

## 路由器 (TL-R5009PE-AC v1.0)

- 固件 1.0.30 Build 20260108。本身不带 Wi-Fi(radio_count=0)，是 PoE·AC 一体 VPN 路由，AP 外接。
- **9 个口全是 2.5G**(10/100/1000/2500M 自协商)，没有独立千兆口。接从机的 WAN 口本身就是 2.5G，不存在被降到千兆。
  官方规格：https://www.tp-link.com.cn/product_3613.html?v=specification
- **整机最大转发带宽 2Gbps**。正好卡在 2000M，没余量；超过 2000(比如 app 测的 2800)过不了这台路由器的 NAT。

## 其他设备规格

### 交换机 TL-SE2106P（2.5G 云管理 PoE）
- 5 个 2.5G 电口 + 1 个万兆 SFP+ 光口，1~4 口 PoE+（整机 65W）
- **所有端口线速转发**，交换容量 ≈ 45Gbps（(5×2.5+10)×2 全双工），包转发率 ≈ 33.5Mpps
- 只做二层转发、不做 NAT，所以它本身不是瓶颈；也替代不了路由器的拨号/NAT
- 官方：https://www.tp-link.com.cn/product_3153.html?v=intro

### 吸顶 AP TL-7AP5100HC-PoE/DC 易展版（BE5100 Wi-Fi 7）
- 有线上联 **1 个 2.5G 口**（非千兆，回程不卡）
- 无线 5G 4323Mbps + 2.4G 688Mbps ≈ 5011（5 流，双频无 6G）；PoE 802.3at 或 DC
- 官方：https://www.tp-link.com.cn/product_3305.html?v=specification

## 全链路瓶颈排序

| 环节 | 上限 |
|---|---|
| 光猫 / FTTR | 2000M 宽带 |
| **路由器 TL-R5009PE-AC** | **~2Gbps NAT 转发（真天花板）** |
| 交换机 TL-SE2106P | 45Gbps 线速（不卡） |
| 吸顶 AP TL-7AP5100HC | 2.5G 回程 / 空口 4323Mbps（不卡） |
| M1 MacBook（Wi-Fi 6） | ~600-900（这台设备的瓶颈） |
| Wi-Fi 7 手机 | 空口可超 2.5G |

真正把 2000M 之上压住的是路由器的 2Gbps NAT。要再往上就得换转发能力更高的路由。

## 登录脚本 `scripts/router.py`

凭据从 `.env` 读(ROUTER_URL / ROUTER_USER / ROUTER_PASSWORD)。只读查询。

```bash
python3 scripts/router.py                 # 打印型号 / WAN / LAN 通断 / 接口模式
python3 scripts/router.py --stok          # 只登录，打印 stok
python3 scripts/router.py '{"network":{"name":"wan_status"},"method":"get"}'   # 任意只读查询
```

### 登录原理(SLP 固件，get_encrypt_info 返回 encrypt_type=["-3"])

1. `POST / {"method":"do","user_management":{"get_encrypt_info":null}}` → 拿 `nonce`、RSA 公钥、`encrypt_type`
2. `-3` 走固定字典：`口令 = securityEncode(密码, "RDpbLfCPsJZ7fiv", 大字典)`(脚本里有实现)
3. `POST / {"method":"do","login":{"username":"admin","password":口令}}` → 返回 `stok`
4. 之后查询 `POST /stok=<stok>/ds`，body 形如 `{"模块":{"name":"表"},"method":"get"}`

### 已知可用的只读表

| body | 内容 |
|---|---|
| `{"device_info":{"name":"info"},"method":"get"}` | 型号、固件版本 |
| `{"network":{"name":"wan_status"},"method":"get"}` | WAN IP、网关、link 状态、实时上下行 |
| `{"network":{"name":"lan_status"},"method":"get"}` | lan_1~8 的 link 通断(phy_status 0/1) |
| `{"network":{"name":"if_mode"},"method":"get"}` | wan_mode、口数、switch 状态 |

**注意**：这固件的 API 只给端口 link 通断，**不暴露协商速率(2.5G/1G)**。要确认实际协商速率只能看设备面板灯或有线实测。

### 探索结论（2026-11-19）

- **路由器超级管理员**：没有。`get_encrypt_info` 返回 `username_type: one_username`，设备是 `sales_method: channel`(零售版、非电信定制)，就一个 admin 账号，没有电信那种超级管理员。
- **光猫到路由的协商速率**：现有权限看不到。
  - 路由器侧只给 link 通断，不给速率(见上)。
  - 光猫侧要用 telecomadmin 才看得到端口速率，但 **telecomadmin 登录会锁定**(`.env` 里的密码应该是错/过期的，连错几次把账号锁了，别再试)。
  - useradmin 能登(华为光猫走 `/cgi-bin/luci` 普通表单 POST，`username`+`psd` 明文，先 GET 建 sysauth cookie 再 POST)，但菜单受限，读不到端口协商速率。
  - 要确认实际协商到 2.5G：看路由器 WAN 口/从机 2.5G 口的面板灯，或有线 iperf 实测。

## 测速脚本 `scripts/speedtest.sh`

用 Ookla `speedtest`(跟手机测速 app 一套)。测速前临时关 macOS 系统代理(Clash Verge 那层，否则 Ookla 走 CFNetwork 被导去香港节点)，测完(含 Ctrl-C)自动恢复；没开代理就不碰。

```bash
bash scripts/speedtest.sh            # 自动选就近电信/联通节点
bash scripts/speedtest.sh -s 3633    # 指定服务器(3633 = 电信上海)
```

报告写进 `logs/speedtest/`。依赖：`brew tap teamookla/speedtest && brew trust teamookla/speedtest && brew install speedtest`。

### 能测到多少，取决于用哪台设备

| 测试端 | 封顶 |
|---|---|
| M1 MacBook 的 Wi-Fi(Wi-Fi 6, 80MHz, 2 流) | ~600–900 Mbps，**测不到 2000** |
| 2.5G USB-C 有线网卡 | ~2300–2400(2.5G 线速扣开销)，但受路由器 2Gbps 上限 |
| Wi-Fi 7 手机宽频空口 | 可超 2.5G，app 测的 2800 就是这么来的 |

要验证宽带真有 2000+，用 Wi-Fi 7 手机跑 Speedtest app 最直接；这台 Mac 怎么测都到不了。
