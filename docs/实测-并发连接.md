# 实测：两个客户端同时对 sys-botbase 发命令

## 目的

确认两个客户端同时发按键和截图命令，会不会互相干扰（返回内容损坏、卡住、超时）。

## 方法

在 `switch-control` 的 bot 刚打完一局、停在科学家面前（没有对话框）时，bot 先退出，再同时开两个客户端，各 15 次：

- A：只循环截图（`pixelPeek`），模拟 bot 轮询画面。
- B：每次先按一下 B 键，再截图。B 键在没有对话框时没有副作用。
- 先单独跑一次 A 作为基线，再让 A、B 同时跑。
- 检查每张截图是不是完整的 JPEG（`FFD8` 开头、`FFD9` 结尾）、有没有超时或报错、响应时间。

测试脚本不在项目里，保存在会话的临时目录。

## 结果

| | 完整截图 | 损坏 | 错误 | 平均耗时 | 最慢 |
|---|---|---|---|---|---|
| 基线 A（单独） | 15 | 0 | 无 | 0.62s | 1.94s |
| 并发 A（只截图） | 15 | 0 | 无 | 1.50s | 2.74s |
| 并发 B（按 B + 截图） | 15 | 0 | 无 | 1.78s | 3.85s |

## 结论

- 两个客户端同时发命令，返回内容没有损坏或错乱，也没有超时或掉线。
- 代价是变慢：同时有两个客户端时，截图平均耗时是单独时的约 2.4 到 2.9 倍。
- `switch-control` 的 bot 截图超时是 5 秒，并发时最慢的一次是 3.85 秒，没超，但余量不大。同时多开客户端截图，bot 有可能超时。

## 没测到的

- 只测了截图和 B 键，两个客户端同时发不同按键序列的情况没测。按键本身对游戏流程的影响是游戏层面的，和连接数无关，肯定会互相影响。
- 每个客户端只发了 15 次，样本量小。
- 测试时 bot 没有连着，没有测"bot 正在打游戏的同时再开一个客户端"的影响。
- 此前在 bot 运行中另开过一个连接发 `getTitleID`，也正常返回，bot 没受影响。
