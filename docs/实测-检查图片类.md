# 实测：ImageChecker 各方法在真实截图上的表现

## 方法

- 样本：`switch-control` 旧会话和 `logs` 里的真实截图（原始 1280×720 的科学家对话和菜单、1920×1080 的资料页和选择界面、战斗菜单）。
- 同一张图换成 5 种形态再测：原图、1920×1080、960×540、640×360、上下各加 60 像素黑边。
- 测试脚本不在项目里，保存在会话的临时目录。

## 结果

| 方法 | 样本 | 结果 |
|---|---|---|
| `has_text` / `read_text` | 科学家对话框「您现在要出发挑战极巨大冒险吗」「请问您要去找哪个宝可梦呢」 | 5 种形态都读对，`has_text` 都为真 |
| `read_text` | 没有对话框的空闲画面 | 5 种形态都读到空字符串 |
| `selected` | 3 项菜单（现在就出发 / 我想听讲解 / 还是先算了；索尔迦雷欧 / 超梦 / 不指定），选中第 0 项 | 5 种形态都返回 0 |
| `selected` | 没有菜单的空闲画面 | 返回 -1 |
| `is_black` | 纯黑图；空闲画面；战斗画面 | 真；假；假 |
| `color_ratio`（闪光星标区域） | 普通资料页 | 折算成上游的 0 到 255 均值是 0.00 |
| 同上 | 闪光样本（资料页，卡璞鳍鳍） | 26.46 到 27.19（阈值 10），5 种形态都稳定 |
| `match_template` | `fight.png`，在战斗菜单符号区域 | 战斗菜单画面 0.96，其他画面最高 0.22，区分得开 |

## 要注意的地方

- `selected` 只比较几个区域的相对亮度，不判断菜单存不存在。旧截图里有 8 张没有菜单的画面也被判成"选中第 2 项"（第三个区域恰好是暗色）。调用前先用 `has_text` 确认菜单的文字在。
- 「是 / 否」这种 2 项菜单位置不同，选中第 1 项的结果来自 3 个区域里的前 2 个，调用时只传 2 个区域就行。
- 选择界面的粉色背景饱和度本来就高，拿它测闪光星标会得到 255，要用资料页。

## 没测到的

- `match_template` 只测了 `fight.png`，没有"应援"画面，`cheer.png` 没有得到正向结果。
- 属性图标、队友精灵图、球图标的模板没有测。
- 没有真实的招式选择菜单截图，招式的选中检测没测。
- 低分辨率都是从大图缩小得到的，不是真实采集。
