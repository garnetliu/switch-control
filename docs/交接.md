### 2. 读内存替代画面识别
目标：首领、初始、对手、新抓到的、闪光都从内存读，删掉对应的 OCR。

**先测（Switch 充好电、在游戏里时）**

每一项都要确认：
- 读出来的对不对；
- PK8 校验和能不能通过；
- 读的时候游戏卡不卡。读内存要把调试器挂到游戏进程上，旧整合包下测出会卡 2–6 秒，干净系统下还没重测。

| 读什么 | 地址（ForkBot.NET `PokeDataOffsetsSWSH.cs` / `LairBot.cs`） | 什么时候读 |
|---|---|---|
| 最终首领 | 指针 `[[[[[[main+26365B8]+68]+78]+88]+D08]+950]+D0`，344 字节 | 进冒险后、选路线画面上 |
| 3 只初始候选 | heap `0x83E93070`、`0x83E93300`、`0x83E93590`，各 344 字节 | 选初始的画面 |
| 对手 | heap `0x886A95B8` | 每场战斗开始 |
| 自己 | heap `0x886B67C8` | 战斗中 |
| 队友 | heap `0x886BC348`、`0x886B9588`、`0x886BF108` | 战斗中（`0x886B9588` 以前读出过 0，要重测） |
| 抓到的 4 只 | 指针 `[[[[[main+28F4060]+1B0]+68]+X]+58]`，X 依次是 58、60、68、70 | ForkBot 在带走界面读；**要测抓到当时是否已经能读** |
| 界面状态 | heap `0x16E498`（路线图 `0xCAD8`，大厅 `0x8FE0`，结算 `0x8DC0`）；main `0x2955BA0`（战斗菜单 `0x032E`，招式 `0x0387`，抓 `0x03C9`） | 随时 |

**怎么读**
- 命令已经在 `lib/switch.py`：`peek(offset, size)` 读 heap，`peek_main(offset, size)` 读 main，`pointer_peek([A, B, ..., 最后偏移], size)` 读指针链。最后一个偏移只加不读，和 ForkBot 的 `ParsePointer` 一致。
- PK8 解密要写进 `../docker`（纯函数）：
  - 按加密常数异或：种子 = EC，每 2 字节 `seed = seed * 0x41C64E6D + 0x6073`，取高 16 位异或；
  - 再按 `(EC >> 13) & 31` 把 4 个 0x50 字节的块排回原序；
  - 校验和 = 解密后 0x08–0x148 的 u16 相加取低 16 位，要等于 0x06 处的值；
  - 种类在 0x08（u16），PID 在 0x1C；
  - 闪光：`(PID>>16) ^ (PID&0xFFFF) ^ TID ^ SID < 16`，TID 在 0x0C、SID 在 0x0E。
- 种类编号对应数据池里的 `id_num`（`data.rental_pokemon()` / `data.boss_pokemon()`）。

**测通后改流程**
1. **首领**：读内存，「不指定」也就知道首领是谁，不用再做「沿用上一局首领」。
2. **初始**：读 3 只候选，不再 OCR 名字、特性。
3. **对手**：读内存后到数据池查，不再打开详细页 OCR。
4. **新抓到的**：读内存，不再读换人界面的卡片。
5. **闪光**：抓到时就能读的话，在 catch 里判断；不行就在结算界面读。结算不再进资料页一只只看：
   - 列表上光标移到闪光那只（神兽优先，也就是最后一只）；
   - 先按 A，等菜单出来再按 A 进资料页，按截图键；
   - 按 B 回列表，再按截图键；
   - 按 A 选择，一直按 A 到列表消失。
   - 没有闪光就按 B 退出，或者走 keep path 重启。

   资料页「换到前一只」的判断（现在靠读名字）也就不需要了。

## 四、实测得到的结论（别再踩）
- **按键被吞**：主因是旧整合包，换干净大气层后正常。画面刚出来时偶尔还会吞一下，所以推摇杆用 `act_until` 重推（等 2 秒）。
- **A 不能重按**：带走列表上按 A 后，菜单要 1.3 秒才出来，选中项还会闪（一帧认得出、一帧认不出）。重按过一次，第二下 A 直接点了「选择」，差点把非闪光首领带走。
- **风暴提示 OCR 时对时错**：一帧「风暴」、下一帧「风泰」，所以扣命要以「倒下了」为前提。
- **开场镜头上移**：第 3 层标签最高到 0.33。每层只有一帧完整，在 USB 下处理一帧约 0.4 秒，慢在模板匹配，不在截图。
- **闪光检测**：资料页 `SHINY_RECT` 里高饱和像素占比。真闪光 27–58，非闪光 0，门槛 10。
- **截图键 `CAPTURE` 可用**：Switch 上会出现截图提示，但 `pixelPeek` 截不到这个提示。
- **`getTitleID` 会挂调试器**：等游戏启动时会反复调用。
- **USB 和网络同时断开**：先怀疑没电睡眠。

## 附录：出错后接着打的临时脚本
放在 scratchpad 跑：`SWITCH_CONNECTION=usb uv run python resume_battle.py 已抓到(逗号分隔) 剩几条命 自己 队友(逗号分隔)`。
从结算接着走的版本：把 `step` 改成 `"select_pokemon"`，补上 `current.caught` / `num_caught` / `lives` 即可。

```python
import sys

sys.path.insert(0, "/Users/garnet/projects/control-switch")
from dotenv import load_dotenv

load_dotenv()
from lib.log import init_log, log

init_log("start")
from config.game import BOSS
from lib import run, switch
from lib.debug_checker import set_step
from lib.run import _restore_member
from autostep.battle import battle
from autostep.catch import catch
from autostep.initialize import initialize
from autostep.join import join
from autostep.path import path
from autostep.select_pokemon import select_pokemon

switch.connect()
state = run.load()
current = run.start(BOSS, state["plan"])
current.restore_paths(state)
current.candidates, current.selection = state["candidates"], state["selection"]
current.start_members = [{"name_id": state["pokemon"]["name_id"]}] + [
    {"name_id": m["name_id"]} for m in state["team"]
]
current.caught = sys.argv[1].split(",")
current.num_caught = len(current.caught)
current.lives = int(sys.argv[2])
current.pokemon = _restore_member({"name_id": sys.argv[3], "hp": 1.0}, True)
current.team = [_restore_member({"name_id": n, "hp": 1.0}, True) for n in sys.argv[4].split(",")]
current.opponents = {int(k): v for k, v in (state["plan"] or {}).get("opponents", {}).items()}
# 普通关在第 len+1 个节点；首领战设成第 3 个，battle 开头会自己前进到首领节点
current.current_index = min(len(current.caught) + 1, 3)
steps = {
    "initialize": initialize,
    "join": join,
    "path": path,
    "battle": battle,
    "catch": catch,
    "select_pokemon": select_pokemon,
}
step = "battle"
while step is not None:
    log(f"开始 {step}")
    set_step(step)
    step = steps[step]()
```
