# 调研：别的项目怎么选首发、路线、换人（2026-11-21）

找到的同类项目只有两个，是一家：上游 AutoMaxLair（Python，已停更）和它的后继 PokemonAutomation 的 Max Lair 程序
（C++，`PokemonAutomation/Arduino-Source` 的 `SerialPrograms/Source/VideoGames/PokemonSwSh/MaxLair/AI/`）。
网上没找到按 seed 推算路线的工具，中文社区也没有相关的算法。两个项目都不知道 seed，只看画面上的属性图标。

相性（单场的分）两边一样：打出 ÷ 受到，打出含队友，受到 ¼ 打自己 ¾ 打队友，自己用最好的招、对手招式取平均
（`calc_move_score`，就是我们 `scoring.move_score` 的来源）。差别在怎么用它：

| | AutoMaxLair（上游） | PokemonAutomation（后继） |
|---|---|---|
| 选首发 | (对全部租借的平均相性³ × 对首领的相性²)^(1/5) | **只看对首领的相性**（几只可能的首领取平均），路上几关不管 |
| 选路线 | Σ 这一层属性对首领的相性 × 1.0 / 1.1 / 1.2 | Σ 这一层属性对首领的相性 × **1 / 2 / 3**（越后面权重越大，差得多） |
| 抓到后换不换 | 加权几何平均：(对后面租借的平均相性^(3−已抓) × 对首领^2)^(1/(5−已抓))，换和不换比 | **四只对首领的相性相加**，每只按血量打折 (血量 + 命数 − 1) ÷ 命数，**电脑队友 × 0.5**；四种「谁拿」加上「没人拿」排，最高的是自己才换 |
| 研究员 | 换成平均的租借比 | 用「对首领相性排中间的那只租借」当会拿到的，和上面同样的算法比 |
| 加权几何平均（3 − 已抓, 2） | 用 | 代码里还在，但用 `#if 0` 关掉了，改成上面只看首领的相加 |

文件：`PokemonSwSh_MaxLair_AI_SelectStarter.cpp`、`_PathMatchup.cpp`（`evaluate_path`，权重 `{1, 2, 3}`）、
`_SwapCatch.cpp`、`_SwapProfessor.cpp`、`_Tools.cpp`（`evaluate_hypothetical_team`）、`_SelectMove.cpp`。

## 和我们的发现对得上的地方

- 后继项目把「路上几关」从首发、换人的分里拿掉了，全部只看首领；路线权重也加大到 1 / 2 / 3。
  这和逐场校准的结论一致：55% 的倒下、55 局输里 51 局都在首领战（`docs/实测-逐场校准.md`）。
- 它把四只的分**相加**而不是相乘，和「每场预测倒下相加」的思路一样。
- 它把电脑队友的分 × 0.5（注释「NPCs are stupid」），我们是按实测出招比例算的。
- 两个项目都不做战斗模拟，也不算回合数、残血。

### 像上游那样用「平均队友」（`--avg`）

上游预先算相性表时，队友传的是全部租借宝可梦，等于队友那一份对每个候选都一样，分数的差别只来自自己这只。
用具体队友时，候选之间的差别会被「各自换来的队友」带偏。这里全部按平均队友算：
打出 = 自己最好那一招 + 3 × 全部租借按实测出招比例的平均伤害；受到 = ¼ 打自己 + ¾ 打全部租借的平均。

| 图 | 首发 | 路线 | 换法（它选的 / 实测） |
|---|---|---|---|
| 3076（超梦） | **流氓熊猫** 3.88（电蜘蛛 2.88） | **斧牙龙 → 堵拦熊 → 狃拉，第 1**（心蝙蝠那条第 3） | 不换、不换、不换 / 一样 |
| 12873（蝶蝶） | **火焰鸡** 3.08（力壮鸡 2.23） | **托戈德玛尔 → 双剑鞘 → 三地鼠，第 1**（魔墙人偶那条第 7） | 换、不换、不换 / 不换、不换、换 |
| 9960（蝶蝶） | **古空棘鱼** 3.72 | **钻角犀兽 → 三地鼠 → 托戈德玛尔，第 1** | 不换、换、不换 / 换、不换、不换 |

同一种算法下，三张图的首发和路线都是实测的那种；换法只有 3076 对上。
（能判断的实测只有这三张图，3076 那组本身不显著，见 `实测-逐场校准.md`。）

## 写进代码（2026-11-21）

`src/swsh/lair/upstream.py` 改成上面「平均队友」的选法，`join.py`、`catch.py`、`path.py` 调用的地方不变（只改了注释和日志）：

- `Scorer.average_matchup`：平均队友的相性；`starter_score` = 对首领的相性；`route_score` = Σ (1, 2, 3) × 对首领的相性；
  `team_score` = 自己 + 0.5 × 三个队友。
- `decide_catch`：五种情况比队伍分，最高的是自己拿才换（日志「自己换成 X 的队伍分 a，没人拿或队友拿里最高的 b」）。
- `decide_scientist`：按 seed 算出研究员实际会给的那只（`Walker.offer`），换成它后队伍分更高就换（11-22 改；测试时用的是「排中间的租借」）。
- `Scorer.matchup`（带具体队友）留着，只给探索脚本用。

核对（`打分算法探索脚本/版本12-上游算法核对.py`）：3076 首发、路线、换法都和实测最好的一样；12873、9960 首发、路线一样，
换法不同（12873 选换、不换、不换，实测不换、不换、换；9960 选不换、换、不换，实测换、不换、不换），和版本 22 `--avg` 的结果一致。

## 「不抓」写进代码（2026-11-22）

每一关打赢后三选一：抓了换、抓了不换（按 seed 推出实际谁换上）、不抓（队伍不变），比队伍分。
`catch.py` 在「捕捉 / 不捕捉」那一步先决定，不抓就按下、按 A（误进选球界面就按 B 退回重来）；
打到第几关改用 `GameState.cleared`，不抓的关记在 `GameState.skipped`，`choices` 里不抓记成 None。

**不抓时随机数照样抽（实测）**：seed 3076008315599927110（首领克雷色利亚，熊猫首发，斧牙龙 → 堵拦熊 → 狃拉）第 1 关不抓。
两种推法在研究员那里不一样：不抽数的话队友不换，第 2 关队伍还是 熊猫 / 沙铃仙人掌 / 电蜘蛛 / 死神棺；
照样抽（和「抓了不换」抽一样多）的话，队友把死神棺换成呆壳兽。日志里第 2 关的队伍是 熊猫 / 沙铃仙人掌 / 电蜘蛛 / 呆壳兽，
所以是照样抽，`Walker.skip` 改成这样。「不捕捉」的按键操作这一局一次就成功了，没有确认框。

**更正（同一天第二局）**：不抓挡不住队友换。两局里自己选「不捕捉」后，画面上都出现「富久决定带走斧牙龙了！」：
死神棺那个队友（富久）拿走了斧牙龙，研究员那里又换成呆壳兽（之后的战斗文字都是「富久的呆壳兽」）。
所以不抓和「抓了不换」完全一样，随机数一样、队友照样拿，自己只是少抓一只（不能带走、不查闪光）。
`Walker.skip` 改成和抓了不换一样，决定时不抓的分等于不换的分，按「一样高先不换」实际不会再选不抓。
「打过了不抓来防止队友换人」这个想法不成立。

**单独再测一次（后面没有研究员）**：seed 31727804189680776（海魔狮首发，焰后蜥 → 流氓熊猫 → 树才怪），第 1 关强制不抓。
画面上「雅文决定带走焰后蜥了！」，第 2 关队伍从 海魔狮 / 败露球菇 / 卡咪龟 / 掘地兔 变成 海魔狮 / 败露球菇 / 卡咪龟 / **焰后蜥**，
和按 seed 推的「抓了不换时掘地兔那个队友拿走焰后蜥」完全一样，中间没有研究员。确认：不抓挡不住队友换。
（这局是测试，强制三关都不抓 / 不换，首领战输了。）

**去掉「不抓」（同一天）**：既然不抓和抓了不换完全一样，代码里的不抓全部去掉，恢复成每一关「抓了换 / 抓了不换」二选一
（不换按 seed 推出实际是哪个队友换上，比队伍分，一样高时不换）。`cleared`、`skipped`、`Walker.skip`、选「不捕捉」的按键都删了。
