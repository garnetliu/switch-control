# 重构：需求和定下的结构

这份文件是审查任务拆分时交给审查方的输入。里面只写已经定下来的需求和结构，不写任务怎么拆。

## 项目现状

- 用电脑控制 Switch 自动刷闪光宝可梦，有两个脚本：
  - `swsh/lair`：剑盾的极巨大冒险。
  - `sv/outbreak`：朱紫的大量出现。
- 现在通过 Switch 上的 botbase 插件（需要大气层）做三件事：截图、按键、读写游戏内存。连接方式有 WiFi（sys-botbase）和 USB（usb-botbase）两种。
- 代码在 `src/` 下，直接放了 `libs`、`tools`、`type`、`sv`、`swsh` 五个目录和 `main.py`、`restart.py`、`scripts.py`，靠 `python src/main.py` 运行。没有测试，没有类型检查。
- `libs/switch.py` 的 `Switch` 一个类里同时有：连接、截图和按键和读内存的方法、配置、这一局的截图、通知。两个脚本各有一个继承它的类，再加上自己的状态。

## 需求

### 结构

1. 所有代码收进一个包 `src/control_switch/`，测试放在和 `src` 平级的 `tests/`，配置都写在 `pyproject.toml`。
2. 运行方式改成命令行入口，不再靠 `python src/main.py`。
3. 包里按做什么事来分目录，不用 `libs`、`tools` 这种名字。不用和 Python 内置名字重名的包名。
4. `control_switch` 是一个程序，不是给别人引用的库，对外只有命令行入口。

### 设备

5. 取图、按键、读写内存是三种能力，各是一个接口。
6. 每种能力可以有不同的硬件来提供：
   - 取图：botbase，或者采集卡。
   - 按键：botbase，或者单片机（串口）。
   - 内存：botbase，或者没有。
7. 三种能力可以随意组合，用哪种由 `.env` 里的三项配置各自决定，和跑哪个脚本无关。
8. 不事先规定哪些组合能用。接不通的组合由启动检查报错。
9. `device` 对外只有两样东西：三个接口，以及创建设备和检查设备的函数。具体的实现类不对外，`device` 外面的代码不引用它们。
10. 朱紫的大量出现从头到尾依赖读写内存，所以 botbase 连接、读写内存、PKHeX 服务都要长期保留，不是过渡期的东西。
11. 极巨大冒险的目标是以后不依赖内存，但这次重构不改它读内存的地方。

### 脚本

12. 每个脚本声明自己需要哪些能力，不管由哪种硬件提供。
13. 脚本不自己创建连接，设备由入口统一创建后交给脚本。
14. 游戏专用的代码只引用设备接口，不引用具体的设备实现。

### 启动检查

15. 启动时统一检查，不通过就报错退出，报错里写明是哪个设备、哪一步没通过。
16. 检查的内容：
    - 配置的值认不认识。
    - 脚本需要的能力有没有配。
    - 取图：能拿到一帧，能解码，是 16:9。
    - 按键：连接能建立（单片机是串口能打开、发命令有回应）。
    - 内存：能读到前台游戏，并且是这个脚本对应的游戏。
    - 按键和画面是不是同一台机器：按一下 HOME 看画面有没有变，再按回去。
17. 原来散在各脚本第一步里的「前台是不是这个游戏」的检查，统一到启动检查里。

### 重构的做法

18. 重构期间不改游戏逻辑：坐标、阈值、步骤、打分都不动。
19. 分成一个一个任务按顺序做，每个任务做完项目都能照常跑。
20. 每个任务过三个角色：写测试、实现、测试。每个角色只看到当前任务的文件。
21. 从重构前原样移动过来的代码，和新写的代码一个标准，要完整地测。
22. 测试的角色站在使用者的角度检查有没有做完、做对、写法好不好；确认是问题的，写一条能复现它的测试用例留在项目里。
23. 每个任务做完，类型检查 0 报错，范围是 `src/control_switch/` 和 `tests/`。
24. 写法对照 `.claude/skills/` 下的规范。
25. 取图、按键、内存的各种组合要有专门的验证，包括接错的情况。

### 硬件

26. 一台破解的 Switch，一台没破解的 Switch。
27. 采集卡：USB 3.0，MS2130 芯片，在 Mac 上是免驱的摄像头设备。Switch 要插在底座上才有画面输出。
28. 单片机：Arduino Uno R3，USB 芯片是 ATmega16U2。16U2 刷成手柄固件后板子的 USB 口插 Switch 底座，Mac 通过 USB 转串口模块接板子的串口引脚发命令。
29. 还没定的：采集的画面要不要缩到 720p；单片机用哪个固件，也就是串口命令的格式。

### 各层的规则

- `device/base.py` 定义三个接口，其他地方只引用接口。
- 三项都选 botbase 时共用同一个连接。
- `session.py` 持有三个设备，以及 `config`、`step`、`frames`、`notifier`。内存可以是空的。步骤里 `sw.click(...)` 的写法不变。
- 两个脚本原来继承连接类的那两个类，不再继承连接。
- 依赖方向：`games` → `flow` → `vision`；`games`、`flow` 通过 `session` 用设备接口。`device`、`vision` 不引用 `games`，`vision` 不引用 `device`。
- 测试里用假的取图、按键、内存设备，步骤和通用操作不接真机也能测。
