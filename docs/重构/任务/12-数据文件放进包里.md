# 任务 12：数据文件放进包里

## 目标

仓库根目录的 `data/` 挪进包里，放在用它的游戏旁边，代码用 `importlib.resources` 找到它，不再按仓库根目录拼路径。挪完以后根目录没有 `data/`。

依据：

- setuptools 文档（Data Files Support）：包自己用的数据文件，最常见的做法是放在包目录里面；读这些文件现在推荐用 `importlib.resources`。
- `data/` 里的文件都是程序运行要用的资源。`lair_event_LUT.json` 现在会写，是因为 30 个布局的事件还没记全；`GameData.record_lair_events` 遇到已经记过、内容一样的位置直接返回，不写文件，记全以后它和别的 `*_LUT.json` 一样只读。

不改任何游戏逻辑，文件内容一个字节都不动。

## 约定

### 新位置

| 原来 | 挪到 |
|---|---|
| `data/swsh/`（整个目录，包括 `type_icons/`） | `src/control_switch/games/swsh/data/` |
| `data/sv/fly_icon.png` | `src/control_switch/games/sv/data/fly_icon.png` |

用 `git mv` 挪，保留历史。`data/` 挪空以后删掉。

数据目录里不放 `__init__.py`，它不是 Python 包。

### 代码里怎么找到它

- `GameConfig.data_dir` 改成 `Path(str(files("control_switch.games.swsh") / "data"))`，`files` 来自 `importlib.resources`。类型还是 `Path`，`GameData` 和测试不用改。
  包装成普通目录（editable 安装、wheel 解压到 site-packages）时 `files()` 返回的就是磁盘上的目录，可以写。这个项目不打包成 zip，不考虑 zip 的情况。
- `EggConfig.fly_icon` 同样改成 `Path(str(files("control_switch.games.sv") / "data" / "fly_icon.png"))`。
- 这两处改完以后，包里不再有 `ROOT / "data"`。

### 打包

hatchling 默认把包目录下不在 `.gitignore` 里的文件都打进 wheel，不用加配置。要用 `uv build --wheel` 实际打一次，确认 json 和 png 都在 wheel 里（见「测试」）。
