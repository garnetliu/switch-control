# 任务 07：脚本声明需要的能力，启动时检查

## 目标

每个脚本写明自己需要取图、按键、内存里的哪几样；启动时统一检查设备，不通过就报错退出，报错里写明是哪个设备、哪一步没通过。原来散在各脚本第一步里的「前台是不是这个游戏」的检查挪到这里。

## 开始前的状态

- `__main__.py` 的 `run`：`load_settings()` → `create_devices(settings)` → `script.SESSION(settings, devices)` → 初始化日志 → 逐步跑。`restart` 类似，最后调 `flow.restart`。
- `Devices` 有 `screen`、`controller`、`memory` 三个字段，`memory` 可以是 `None`。
- 两个脚本的第一步各自检查了游戏：
  - `games/swsh/lair/steps/initialize.py`：读 `title_id`，不在 `sw.config.game_title_ids` 里就抛 `RuntimeError`。
  - `games/sv/outbreak/steps.py` 的 `initialize`：同样的检查。
- `games/sv/__init__.py`、`games/swsh/__init__.py` 里各有一个 `TITLE_IDS`。
- `flow/restart.py` 里有一个内部函数 `_home_shown(sw, screen)`，判断画面是不是 HOME 菜单。

## 约定

### 脚本

两个脚本的 `__init__.py` 各加两项：

- `REQUIRES`：`frozenset`，里面是 `"screen"`、`"controller"`、`"memory"`。两个脚本现在都是三样都要。
- `TITLE_IDS`：从所属游戏的 `__init__.py` 引用过来。

### `device/check.py`

- `DeviceCheckError`，继承 `RuntimeError`。
- `check_devices(devices, requires, title_ids)`，`title_ids` 可以是 `None`。按顺序检查，遇到第一个不通过的就抛 `DeviceCheckError`：
  1. `requires` 里有 `"memory"` 而 `devices.memory` 是 `None`：报错说明这个脚本要读内存，`MEMORY` 不能是 `none`。
  2. 取图：`pixel_peek()` 拿一张图。拿不到或解码不了，报错；宽高比不是 16:9（差超过 0.01），报错并写出实际的宽高。整张图全黑不算错，记一条警告日志，提示可能没有画面输出。
  3. 游戏：`devices.memory` 不是 `None` 而且 `title_ids` 不是 `None` 时，读 `title_id()`。读出来是空的，报错说明没有游戏在运行；不在 `title_ids` 里，报错并写出读到的值。
- 每条报错的开头写明是哪一类：`取图`、`按键`、`内存`。
- 这个文件不引用 `vision`、`flow`、`games`。
- `device/__init__.py` 多导出 `check_devices`、`DeviceCheckError`。

### `flow/check.py`

- `flow/restart.py` 的 `_home_shown` 改名 `home_shown`，变成对外的。
- `check_controller_reaches_screen(sw)`：确认按键真的送到了画面上的这台 Switch。
  1. 截一张图，记下现在是不是 HOME 菜单。
  2. 按一下 HOME，等画面变成另一种状态（原来不是 HOME 就等 HOME 出现，原来是 HOME 就等 HOME 消失）。
  3. 再按一下 HOME，等画面回到原来的状态。
  4. 任何一步等超时，抛 `DeviceCheckError`，说明按了 HOME 画面没有变化，可能是按键没有送到，或者取图和按键接的不是同一台。
- 等待的时间用 `BaseConfig` 上新加的 `check_timeout = 10.0`。

### 入口

- `run`：`create_devices` → `check_devices(devices, script.REQUIRES, script.TITLE_IDS)` → `script.SESSION(...)` → 初始化日志 → `check_controller_reaches_screen(sw)` → 逐步跑。
- `restart`：`create_devices` → `check_devices(devices, script.REQUIRES, None)` → 之后和原来一样。重启时游戏可能已经崩了，所以不检查游戏，也不做 HOME 那项。
- 检查不通过时打印报错并以非 0 退出，不发通知。

## 写测试

只能改 `tests/`。用 `tests/conftest.py` 里的假设备。

1. `tests/device/test_check.py`
   - 三样都正常：不抛。
   - `requires` 有 `"memory"`、`memory` 是 `None`：抛 `DeviceCheckError`，报错里有 `MEMORY`。
   - `requires` 没有 `"memory"`、`memory` 是 `None`：不抛。
   - 取图返回空字节：抛，报错以 `取图` 开头。
   - 取图返回不是图片的字节：抛。
   - 取图返回一张 4:3 的图：抛，报错里有实际的宽高。
   - 取图返回全黑的 16:9 图：不抛，有一条警告日志。
   - `title_id` 返回空字符串：抛，报错以 `内存` 开头。
   - `title_id` 返回别的游戏：抛，报错里有读到的值。
   - `title_id` 大小写、前后空白不同但是同一个游戏：不抛。
   - `title_ids` 传 `None`：不读 `title_id`。
2. `tests/flow/test_check.py`，把 `home_shown` 换成按事先给定的顺序返回 True 或 False 的函数：
   - 原来不在 HOME：按了两次 HOME，不抛。
   - 原来在 HOME：按了两次 HOME，不抛。
   - 第一次按完画面一直不变：抛 `DeviceCheckError`，只按了一次。
   - 第二次按完画面一直不回去：抛 `DeviceCheckError`。
3. `tests/games/test_registry.py` 补：两个脚本都有 `REQUIRES`（是 `{"screen", "controller", "memory"}` 的子集）和 `TITLE_IDS`（不为空）。
4. `tests/test_main.py` 补，把 `create_devices` 换成返回假设备的函数：
   - `run`：假 `Memory` 返回别的游戏的 `title_id` 时，`main` 以非 0 退出，没有创建 `SESSION`。
   - `restart`：同样的假设备，不因为游戏不对而退出。

## 实现

不能改 `tests/`。

1. 新建 `device/check.py`、`flow/check.py`，按「约定」写。
2. `flow/restart.py`：`_home_shown` 改名 `home_shown`，文件里用到的地方跟着改。
3. `config.py` 的 `BaseConfig` 加 `check_timeout`，写上注释。
4. 两个脚本的 `__init__.py` 加 `REQUIRES`、`TITLE_IDS`。
5. 去掉两个脚本第一步里对 `title_id` 的检查，其余不动：
   - `games/swsh/lair/steps/initialize.py`
   - `games/sv/outbreak/steps.py` 的 `initialize`
6. `__main__.py` 按「入口」改。
7. `README.md` 加一段：启动时检查什么，报错分别是什么意思。

## 要在真机上确认的

- 正常情况：`make start` 开始时画面会切到 HOME 再切回游戏，然后照常跑。
- 游戏没开时 `make start`：报错说明没有游戏在运行。
- 开着朱紫跑 `make start script=swsh/lair`：报错说明游戏不对，并写出读到的 Title ID。
- `make restart` 在游戏崩了的时候仍然能用。
- 开始时人已经在 HOME 菜单上，`make start` 也能通过检查。
