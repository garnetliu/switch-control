# 任务 07：脚本声明需要的能力，启动时检查

## 目标

每个脚本写明自己需要取图、按键、内存里的哪几样；启动时统一检查设备，不通过就报错退出，报错里写明是哪个设备、哪一步没通过。原来散在各脚本第一步里的「前台是不是这个游戏」的检查挪到这里。

## 开始前的状态

- `__main__.py` 的 `run`：`load_script(name)` → `load_settings()` → `create_devices(settings)` → `script.SESSION(settings, devices)` → 初始化日志 → 逐步跑。`restart` 类似，最后调 `flow.restart`。
- `Devices` 有 `screen`、`controller`、`memory` 三个字段，`memory` 可以是 `None`。
- 两个脚本的第一步各自检查了游戏：
  - `games/swsh/lair/steps/initialize.py`：读 `title_id`，不在 `sw.config.game_title_ids` 里就抛 `RuntimeError`。
  - `games/sv/outbreak/steps.py` 的 `initialize`：同样的检查。
- `games/sv/__init__.py`、`games/swsh/__init__.py` 里各有一个 `TITLE_IDS`。
- `flow/restart.py` 里有一个内部函数 `_home_shown(sw, screen)`，判断画面是不是 HOME 菜单。
- 工作区是干净的：上一个任务的改动已经提交，`git status --short` 没有输出。不干净时先停下来问，不要开始。

## 约定

### 脚本

两个脚本的 `__init__.py` 各加两项：

- `REQUIRES`：`frozenset`，里面是 `"screen"`、`"controller"`、`"memory"`。两个脚本现在都是三样都要。
- `TITLE_IDS`：从所属游戏的 `__init__.py` 引用过来。

### `device/check.py`

- `DeviceCheckError`，继承 `RuntimeError`。
- `check_requires(settings, requires)`：`requires` 里有 `"memory"` 而 `settings.memory` 是 `"none"` 时，抛 `DeviceCheckError`，报错和下面 `check_devices` 第 1 步一样。只看配置，不碰设备，入口在 `create_devices` 之前调它。
- `check_devices(devices, requires, title_ids)`，`title_ids` 可以是 `None`。按顺序检查，遇到第一个不通过的就抛 `DeviceCheckError`：
  1. `requires` 里有 `"memory"` 而 `devices.memory` 是 `None`：报错说明这个脚本要读内存，`MEMORY` 不能是 `none`。
  2. 取图：`pixel_peek()` 拿一张图。`pixel_peek()` 抛异常、返回空字节、解码抛异常或返回 `None`，都报错；空字节要在解码前先判断，`cv2.imdecode` 遇到空字节抛 `cv2.error`，不是返回 `None`。宽高比不是 16:9（差超过 0.01），报错并写出实际的宽高。整张图全黑不算错，记一条警告日志，提示可能没有画面输出。全黑的标准和 `ImageChecker.is_black` 一样：图转成 HSV 后，亮度（V 通道）不超过 50 的像素至少占 98%，并且亮度的标准差不超过 10。在这个文件里用 `cv2` 自己算，不引用 `vision`。警告用 `logging.warning(...)` 直接写根 logger，不用 `logging.getLogger(__name__)`：`log.py` 的输出只放过根 logger 的记录，别的名字在终端和日志文件里都看不到。
  3. 游戏：`devices.memory` 不是 `None` 而且 `title_ids` 不是 `None` 时，读 `title_id()`。`title_id()` 抛异常（超时、断开、USB 出错）时，报错以 `内存` 开头，后面接原来的报错。读到的值先 `strip().upper()`，再判断是不是空和比较；`title_ids` 里都是大写。处理后是空的，报错说明没有游戏在运行；不在 `title_ids` 里，报错并写出处理后的值。
- 每条报错的开头写明是哪一类：`取图`、`按键`、`内存`。
- 按键：botbase 的按键能不能用，在 `create_devices` 连接时就确认了，`check_devices` 里不再单独检查。
- 这个文件不引用 `vision`、`flow`、`games`。
- `device/__init__.py` 多导出 `check_requires`、`check_devices`、`DeviceCheckError`。

### `device/factory.py`

- `create_devices`：`connect_botbase` 抛 `OSError`（`ConnectionError`、连接超时、USB 的错误都是它的子类）时，改抛 `DeviceCheckError`。报错开头写用 botbase 的那几类，后面写 botbase 连接失败、是 WiFi 还是 USB，再接原来的报错，例如三项都用 botbase 时是 `取图、按键、内存：botbase（USB）连接失败：找不到 usb-botbase……`。

### `flow/check.py`

- `flow/restart.py` 的 `_home_shown` 改名 `home_shown`，变成对外的。
- `flow/check.py` 用 `from .restart import home_shown` 引用它；测试里替换 `control_switch.flow.check.home_shown`。
- `check_controller_reaches_screen(sw)`：确认按键真的送到了画面上的这台 Switch。
  1. 截一张图，记下现在是不是 HOME 菜单。
  2. 按一下 HOME，等画面变成另一种状态（原来不是 HOME 就等 HOME 出现，原来是 HOME 就等 HOME 消失）。
  3. 再按一下 HOME，等画面回到原来的状态。
  4. 任何一步等超时，抛 `DeviceCheckError`，说明按了 HOME 画面没有变化，可能是按键没有送到，或者取图和按键接的不是同一台。
- 等待的时间用 `BaseConfig` 上新加的 `check_timeout = 10.0`。
- 记日志直接用 `logging.info(...)`、`logging.warning(...)` 写根 logger，不用 `logging.getLogger(__name__)`，原因和 `device/check.py` 一样。

### `log.py`

- `_get_logger` 改名 `init_console`，变成对外的，做的事不变：给根 logger 加终端输出，已经有了就不加。`init_log`、`new_log` 里调它的地方跟着改。

### 入口

- `run`：`init_console()` → `script = load_script(name)` → `settings = load_settings()` → `check_requires(settings, script.REQUIRES)` → `devices = create_devices(settings)` → `check_devices(devices, script.REQUIRES, script.TITLE_IDS)` → `sw = script.SESSION(settings, devices)` → `init_log(sw, "start")` → `check_controller_reaches_screen(sw)` → 逐步跑。
- `restart`：`init_console()` → `script = load_script(name)` → `settings = load_settings()` → `check_requires(settings, script.REQUIRES)` → `devices = create_devices(settings)` → `check_devices(devices, script.REQUIRES, None)` → `sw = script.SESSION(settings, devices)` → `init_log(sw, "restart")` → `restart(sw)`，不管成功还是出错，最后都 `sw.close()`。重启时游戏可能已经崩了，所以不检查游戏，也不做 HOME 那项。
- 脚本名不对时 `load_script` 直接退出，不去连接。
- `init_console()` 要在第一条日志之前调。根 logger 还没有输出时记日志，Python 会自动加一个默认格式的终端输出，之后 `log.py` 就不再加自己的，整次运行的终端日志都没有时间，也不挡第三方库的日志。
- `check_devices` 记的全黑警告只打到终端，不进日志文件：日志文件的目录在脚本的配置里，要等 `script.SESSION(...)` 创建以后才有。
- `check_requires`、`create_devices`、`check_devices`、`check_controller_reaches_screen` 抛 `DeviceCheckError` 时，打印报错并以非 0 退出，不发通知。
- `load_settings` 抛 `ValueError`（配置的值不认识、`SWITCH_PORT` 不是整数），`create_devices` 抛 `ValueError`（WiFi 连接缺 ip 或端口；没装 libusb 时 pyusb 抛的 `NoBackendError` 也是 `ValueError`）或 `NotImplementedError`（选了还没实现的 `capture`、`serial`），也这样处理：打印报错并以非 0 退出，不打印 traceback，不发通知。只处理这两个函数抛的，逐步跑时抛的 `ValueError` 不管。
- `__main__.py` 用 `from control_switch.device import check_devices, check_requires, create_devices`、`from control_switch.flow.check import check_controller_reaches_screen`、`from control_switch.log import init_console, init_log` 引用；测试里替换的是 `control_switch.__main__` 上的这些名字。
