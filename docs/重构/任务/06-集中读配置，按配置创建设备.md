# 任务 06：集中读配置，按配置创建设备

## 目标

读环境变量的地方集中到 `settings.py` 一个文件；新增 `SCREEN`、`CONTROLLER`、`MEMORY` 三项配置，由 `device/factory.py` 按配置创建设备。这次只有 botbase 一种实现，三项都不写时和现在的行为完全一样。

## 开始前的状态

- 读环境变量的地方分散在：
  - `device/botbase.py` 的 `connect_botbase`：`SWITCH_CONNECTION`（不写是 `wifi`）、`SWITCH_IP`、`SWITCH_PORT`
  - `notifier.py`：`DISCORD_WEBHOOK_URL`
  - `pkhex.py`：`PKHEX_API_URL`（`Pkhex` 的构造参数 `api_url` 没传时读）
  - `games/swsh/lair/game_state.py`：`KEEP_PATH`（等于 `"1"` 才算开）
- `__main__.py` 里先 `load_dotenv()`，再 `load_script(name)`，再 `connect_botbase()`，再 `script.SESSION(botbase, botbase, botbase)`。
- `scripts/find_switch.py` 自己读 `SWITCH_MAC`，它是单独运行的，这次不动。
- 工作区是干净的：上一个任务的改动已经提交，`git status --short` 没有输出。不干净时先停下来问，不要开始。

## 约定

### `settings.py`

- `Settings`：不可变的 dataclass。

| 字段 | 环境变量 | 不写时 | 可以写的值 |
|---|---|---|---|
| `screen` | `SCREEN` | `"botbase"` | `botbase`、`capture` |
| `controller` | `CONTROLLER` | `"botbase"` | `botbase`、`serial` |
| `memory` | `MEMORY` | `"botbase"` | `botbase`、`none` |
| `switch_connection` | `SWITCH_CONNECTION` | `"wifi"` | `wifi`、`usb` |
| `switch_ip` | `SWITCH_IP` | `None` | |
| `switch_port` | `SWITCH_PORT` | `None` | 整数 |
| `pkhex_api_url` | `PKHEX_API_URL` | `None` | |
| `discord_webhook_url` | `DISCORD_WEBHOOK_URL` | `None` | |
| `keep_path` | `KEEP_PATH` | `False` | 等于 `"1"` 才是 `True` |

- `load_settings(env: Mapping[str, str] | None = None) -> Settings`：`env` 不传时先 `load_dotenv(ROOT / ".env")`（`ROOT` 来自 `config.py`，是仓库根目录；不覆盖已经有的环境变量），再读 `os.environ`；传了 `env` 时只读传进来的字典，不读 `.env`。有可选值的几项不分大小写，值不认识时抛 `ValueError`，报错里用环境变量名（大写，如 `SCREEN`）写明是哪一项，再写出写了什么、可以写什么，例如 `SCREEN 写的是 hdmi，可以写 botbase、capture`。`SWITCH_PORT` 不是整数时同样报错，报错里有 `SWITCH_PORT`。空字符串当作没写。
- `settings.py` 用 `from dotenv import load_dotenv` 引入；测试里替换 `control_switch.settings.load_dotenv`。
- `settings.py` 之外，`src/control_switch/` 里不再读环境变量，也不再调用 `load_dotenv`。

### `device/factory.py`

- `Devices`：`NamedTuple`，三个字段 `screen`、`controller`、`memory`，`memory` 可以是 `None`。
- `create_devices(settings) -> Devices`：
  - 三项里选了 `botbase` 的共用同一个 `Botbase`，只连接一次。
  - 三项都没选 `botbase` 时不去连接。
  - `MEMORY=none` 时 `memory` 是 `None`。
  - `capture`、`serial` 这次还没有实现，抛 `NotImplementedError`，报错里用环境变量名（`SCREEN`、`CONTROLLER`）写明是哪一项。先把三项都检查完，有没实现的就抛，不去连接 botbase。
- `connect_botbase` 改成接收 `settings`：`connect_botbase(settings)`。WiFi 连接但没有 ip 或端口时抛 `ValueError`，报错里用环境变量名 `SWITCH_IP`、`SWITCH_PORT` 说明缺哪一项。
- `device/__init__.py` 多导出 `Devices`、`create_devices`。
- `factory.py` 用 `from .botbase import connect_botbase` 引用；测试里替换 `control_switch.device.factory.connect_botbase`。

### 其他地方怎么拿到配置

- `Session(config, settings, devices)`：`settings` 只在创建时用，不挂在 `Session` 上，没有 `sw.settings`。`Session` 创建 `Notifier` 时写 `Notifier(webhook_url=settings.discord_webhook_url)`。`session.py` 用 `from control_switch.notifier import Notifier` 引用；测试里替换 `control_switch.session.Notifier`。
- `Notifier(webhook_url: str | None = None)`：地址只从这个参数来。不传或传 `None` 时和现在没配置一样，不发通知，只提醒一次。
- 脚本的 `SESSION(settings, devices)`。
- `LairSession` 里创建 `Pkhex` 时传 `settings.pkhex_api_url`，`OutbreakSession` 同样。`Pkhex` 里没传地址时用默认地址，不再读环境变量。两个脚本的 `session.py` 用 `from control_switch.pkhex import Pkhex` 引用；测试里替换 `control_switch.games.swsh.lair.session.Pkhex`、`control_switch.games.sv.outbreak.session.Pkhex`。
- `GameState(config: GameConfig, keep_path: bool = False)`：`finish_run` 用 `keep_path` 代替原来读的环境变量 `KEEP_PATH`。`LairSession` 创建它时写 `GameState(config, keep_path=settings.keep_path)`。

### 入口

`script = load_script(name)` → `settings = load_settings()` → `devices = create_devices(settings)` → `sw = script.SESSION(settings, devices)`。脚本名不对时直接退出，不去连接。`__main__.py` 里不再调用 `load_dotenv()`，用 `from control_switch.device import create_devices` 引用 `create_devices`。
