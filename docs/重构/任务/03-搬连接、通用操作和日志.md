## 写测试

只能改 `tests/`。

这次搬进来的文件要完整地测：每个对外的函数和方法至少有一条测试。下面列的是至少要有的，没列到的也要补上。`device/botbase.py` 除外，它后面拆成设备接口时再测。

`scripts/find_switch.py` 也算这次搬的文件，同样要完整地测，测试写在 `tests/scripts/test_find_switch.py`。它不在包里，用 `importlib.util.spec_from_file_location` 按文件路径加载成模块。`make typecheck` 也检查 `tests/`，`spec_from_file_location` 的返回值和它的 `loader` 在类型上都可能是 `None`，加载前写 `assert spec is not None and spec.loader is not None`，不然 pyright 会报错。不要用 `runpy.run_path`：它返回的是全局变量的副本，改了也影响不到函数。用 `monkeypatch` 替换 `subprocess.run`、`socket.socket`、`time.sleep`，不能真的发网络包、跑 `route`、`arp`、`ping`；`SWITCH_MAC` 用 `monkeypatch.setenv` 设；`monkeypatch.setattr(模块, "ROOT", ...)`、`monkeypatch.setattr(模块, "ENV_FILE", ...)` 指到 pytest 的临时目录，不能写到仓库的 `.env` 和 `logs/find/`。`main` 会往根 logger 上加 handler，测试开始前清空根 logger 的 handler，结束时把加上的关掉、清掉。至少要有：`_normalize_mac` 补前导 0、转成小写、`-` 分隔转成 `:`；`find_switch` 在 `arp -an` 的输出里按 MAC 找到 ip，不在本网段的不算，几轮都找不到返回 `None`；`ping` 从输出里解析出平均延迟，没有汇总行时返回 `None`；`main` 找到时把 `SWITCH_IP` 写进 `.env`，找不到时以非 0 状态退出。

在 `tests/conftest.py` 里做一个假的连接，给下面的测试用。它不继承 `Switch`，只要有这些东西：

- `pixel_peek()`：按顺序返回事先给定的图片字节，用完后一直返回最后一张。图片用 `tests/images/` 里的 jpg。
- `click(button, delay)`：把按过的键记在一个列表里，不等待。
- `config`：`interval` 是 0，`timeout` 是 1.0 秒，`log_dir` 指向 pytest 的临时目录（`failed_dir` 是由 `log_dir` 算出来的，会跟着变，不能单独赋值）。超时不要设得比 1 秒短：第一次建 `ImageChecker` 要初始化 OCR，约 0.1 秒，超时太短的话还没判断完就超时了。
- `frames`：空列表。`step`：一个字符串。
- `title_id()`：返回事先给定的值，重启的测试要用。`config` 上重启用到的几项：`game_title_ids` 设成一个元组，里面有 `title_id()` 默认返回的值（`BaseConfig` 上它是空元组，直接用的话重启最后一步永远等不到游戏启动）。这个默认值用大写、不带空白的 16 位十六进制，例如 `"0100ABF008968000"`：重启的代码只把 `title_id()` 读到的值去空白、转大写再和 `game_title_ids` 比，`game_title_ids` 里的值不处理，写成小写的话永远对不上；`load_timeout`、`boot_timeout` 都是 1.0 秒；`rects` 和彩色画面的三项直接用 `BaseConfig` 的。

假的连接通过 fixture 给测试用：fixture 返回一个函数，传入图片列表和 `title_id()` 要返回的值（不传时用默认值），返回一个假的连接。测试文件里不能写 `from conftest import ...`，`importlib` 导入方式下找不到 `conftest`。

测试里把假连接传给 `flow`、`log` 里参数标成 `Switch` 的函数时，写成 `typing.cast(Switch, fake)`，`Switch` 从 `control_switch.device.botbase` 引用；按过的键等记录从假连接本身读。假连接不继承 `Switch`，直接传进去 `make typecheck` 会报参数类型不对，而这次 `flow`、`log` 的参数类型不改，所以只在测试里这样写。

`tests/flow/test_wait.py`：

- `capture`：返回的图能用，`frames` 里多了一条，带着当时的 `step` 和传进去的说明。
- `wait_for`：条件第一次就满足时立刻返回；第 3 张图才满足时返回的是第 3 张；一直不满足抛 `TimeoutError`，报错里有传进去的说明。
- `press_until`：条件一开始就满足时一次都不按；不满足时按的是指定的键。
- `act_until`：动作至少做了一次之后条件满足，返回；一直不满足抛 `TimeoutError`。
- `save_frames`：写出的文件数和 `frames` 一样，文件名是「序号-时分秒-步骤-说明.jpg」，说明里的 `/` 换成了 `_`。

`tests/test_log.py`：

- `new_log` 在 `config.log_dir/名字/` 下建出一个 `.log` 文件。
- `init_log` 连着调两次：根 logger 上只有一个 `logging.FileHandler`，只建了一个 `.log` 文件。
- `new_log` 先后传两个不同的名字：根 logger 上只剩一个 `logging.FileHandler`，是第二个文件的，第一个已经关掉；之后 `logging.info` 的内容只写进第二个文件。文件名只精确到秒，同一个名字一秒内调两次会写进同一个文件，所以要用两个名字。
- `logging.info` 的内容写进了文件；`logging.getLogger("别的名字").warning(...)` 的内容没有写进去。

每条测试开始前把根 logger 上已有的 handler 清空（例如 `monkeypatch.setattr(logging.getLogger(), "handlers", [])`）：pytest 自己会往根 logger 上加 handler，其中一个是 `logging.FileHandler` 的子类，不清掉的话 `init_log` 会以为已经有日志文件，什么都不建。测试结束时把加到根 logger 上的 handler 关掉、清掉，不影响别的测试。

`tests/flow/test_menu.py`，图片从 `logs/keep/` 复制到 `tests/images/`：有菜单的图用 `研究员问换不换.jpg`，没有菜单的图用 `路线上的界面-遇到了背包客.jpg`，找菜单的范围都用 `((0.60, 0.45), (0.90, 0.79))`。期望值用搬之前的代码跑出来的结果。在搬之前的代码上，`研究员问换不换.jpg` 读出两项 `['>是', '定否']`，光标在第 0 项；这是 OCR 读出来的字，和画面上的字不一样，期望值照读出来的写。`路线上的界面-遇到了背包客.jpg` 用这个范围 `find_menu` 返回 `None`。没有光标停在其他选项上的截图，所以用这张图的用例，目标都指向第 0 项（光标已经在目标上）；要光标移动的情况用下面最后一条的做法，替换 `ImageChecker.selected`。`move_menu_option` 按文字找选项时，允许的差别是目标文字长度的三分之一，这张图的选项只有一两个字，所以「差一个字」的用例，目标要写成 3 个字，例如 `">是吗"`。「传了对话区域而那里没有文字」的用例，对话区域用这张图左上角没有字的 `((0.0, 0.0), (0.2, 0.1))`：

- `menu_last_item`：有菜单的图返回最后一项的文字；指定序号时返回那一项；没有菜单的图返回空字符串；传了对话区域而那里没有文字时返回空字符串。
- `move_menu_option`：目标是序号、目标是文字各一条，光标已经在目标上时不移动；目标文字差一个字也能对上；图里没有菜单时抛 `RuntimeError`。
- `move_menu_option`：光标每次都换了位置，但移满选项个数那么多次还没到目标时抛 `RuntimeError`，报错里有「还是没到」。做法：用带菜单的图，目标序号用一个比选项个数大的数，用 `monkeypatch` 把 `ImageChecker.selected` 换成每次调用轮流返回 0 和 1 的函数。

`tests/flow/test_restart.py`，没有 HOME 菜单和选用户界面的截图，把 `ImageChecker` 上用到的判断（`has_text`、`is_black`、`color_ratio`）换成按事先给定的顺序返回结果，用完后一直返回最后一个值（`wait_for` 在超时前会反复调用判断，次数事先定不了；用完就抛 `StopIteration` 或 `IndexError` 的写法，超时的用例拿不到 `TimeoutError`）：

- `restart_to_title`：一开始不在 HOME 时先按 HOME；一开始就在 HOME 时不按 HOME；按 Y 一直按到关闭软件的确认框出现；之后按了两次 A。
- `restart_to_title`：选用户的界面一直不出现时抛 `TimeoutError`。
- `restart_to_title`：按完第二次 A 之后，`title_id()` 返回的是 `game_title_ids` 里那个值的小写、前后带空白的写法（例如 `" 0100abf008968000\n"`），`color_ratio` 不低于 `colorful_ratio` 时正常返回。
- `restart_to_title`：按完第二次 A 之后，`title_id()` 不在 `game_title_ids` 里时，`color_ratio` 再高也一直等，超时抛 `TimeoutError`，报错里有「开场的彩色画面」；`title_id()` 对但 `color_ratio` 一直低于 `colorful_ratio` 时同样超时。
- `enter_game`：画面一开始就是黑的，一次 A 都不按；第 3 张图变黑，按了 2 次 A。
- `restart`：先做完 `restart_to_title` 再做 `enter_game`，按键记录是这两段按顺序合起来的。

`flow/__init__.py` 导出了同名的函数 `restart`，所以 `control_switch.flow.restart` 这个名字拿到的是函数，不是模块。`import control_switch.flow.restart as m` 拿到的也是函数；`monkeypatch.setattr("control_switch.flow.restart.enter_game", ...)` 会报 `AttributeError`。要替换 `flow/restart.py` 里的函数（比如测 `restart` 时把 `restart_to_title`、`enter_game` 换成记下调用顺序的函数），先用 `importlib.import_module("control_switch.flow.restart")` 拿到模块，再写 `monkeypatch.setattr(模块, "enter_game", ...)`。`from control_switch.flow.restart import ...` 不受影响。
