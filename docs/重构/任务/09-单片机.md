# 任务 09：单片机

## 目标

按键可以用单片机（伊机控固件）来按：`CONTROLLER=serial` 时，电脑通过 TTL 串口给单片机发按键报文，单片机当成手柄插在 Switch 底座上。这样没破解的那台 Switch 也能按键。取图、内存这次不动。

## 开始前的状态

- `device/base.py` 有 `Controller` 接口：`click(button, delay=0.15)`、`stick(side, x, y, hold)`、`close()`。
- `device/botbase.py` 的 `Botbase.click` 发 `click <按键名>`，按键名是 botbase 的写法；`stick` 的 `x`、`y` 范围是 `-0x7FFF` 到 `0x7FFF`，x 正数向右、y 正数向上，推 `hold` 秒再回中。
- 代码里用到的按键名：`A`、`B`、`X`、`Y`、`R`、`HOME`、`CAPTURE`、`DDOWN`、`DLEFT`；摇杆只用 `LEFT`。
- `settings.py` 的 `controller` 可以写 `botbase`、`serial`；`device/factory.py` 遇到 `serial` 抛 `NotImplementedError`。
- `device/check.py` 有 `DeviceCheckError`（继承 `RuntimeError`）；`create_devices` 连接 botbase 失败时改抛 `DeviceCheckError`，报错开头写用它的那几类（`取图`、`按键`、`内存`）。入口遇到 `DeviceCheckError` 打印报错、非 0 退出。
- 依赖里已经有 `pyserial`（3.5）。

## 硬件和协议（2026-11-21、11-23 实测）

- 单片机：Arduino UNO R3，USB 芯片 16U2 刷了伊机控 v7 固件（EasyConNS/EasyCon 仓库 `assets/fw/UNO v7.hex`），插在 Switch 底座上，系统认成手柄。
- 电脑通过 TTL（USB 转串口）接单片机的 0、1 号口。macOS 上串口是 `/dev/cu.usbserial-2021230` 这种名字。
- 波特率 **9600**（伊机控源码默认 115200，这块板子实测只有 9600 能通）。
- 命令都以 `A5` 开头，单片机回 1 个字节：

| 命令 | 发送 | 回应 | 实测 |
|---|---|---|---|
| 握手 | `A5 A5 81` | `80` | 7 ms |
| 停止单片机里存的脚本 | `A5 84` | `83` | 5 ms |
| 版本 | `A5 85` | `0x40`–`0x80` 之间是版本号 | `46`（v7.0） |

- 单片机上电后会跑里面存的旧脚本，这时发按键报文回 `FE`（忙）。所以连上后先握手、再发停止脚本，之后按键报文回 `FF`。
- 按键报文：7 个字节 `[按钮高 8 位, 按钮低 8 位, HAT, LX, LY, RX, RY]`，按 7 位一组打包成 8 个字节，每字节低 7 位是数据，最后一个字节最高位置 1。打包算法（EasyCon `SwitchReport.GetBytes`）：

  ```
  n = 0; bits = 0; out = []
  for b in raw:
      n = (n << 8) | b; bits += 8
      while bits >= 7:
          bits -= 7; out.append((n >> bits) & 0x7F); n &= (1 << bits) - 1
  out[-1] |= 0x80
  ```

  中立报文（没按键、HAT 居中、摇杆居中）是 `00 00 01 08 04 02 01 80`，实测回 `FF`，约 12 ms。
- 按钮位：`Y=0x01`、`B=0x02`、`A=0x04`、`X=0x08`、`L=0x10`、`R=0x20`、`ZL=0x40`、`ZR=0x80`、`MINUS=0x100`、`PLUS=0x200`、`LSTICK=0x400`、`RSTICK=0x800`、`HOME=0x1000`、`CAPTURE=0x2000`。
- HAT（十字键）：上 0、右上 1、右 2、右下 3、下 4、左下 5、左 6、左上 7、居中 8。
- 摇杆：每轴 0–255，中心 128；上是 `LY=0`、下是 `LY=255`，左是 `LX=0`、右是 `LX=255`。
- 两次报文之间至少隔 30 ms（伊机控电脑端的最小间隔）。按住多久由「按下的报文」和「松开的报文」之间隔多久决定；松开就是发中立报文。

## 约定

### `settings.py`

| 字段 | 环境变量 | 不写时 | 说明 |
|---|---|---|---|
| `serial_port` | `SERIAL_PORT` | `None` | 串口路径，例如 `/dev/cu.usbserial-2021230` |
| `serial_baud` | `SERIAL_BAUD` | `9600` | 整数，不是整数时抛 `ValueError`，报错里有 `SERIAL_BAUD` |

空字符串当作没写，和其他几项一样。

### `device/serial_pad.py`

- 类 `SerialPad`，实现 `Controller`。`device` 外面不引用它。
- 构造：`SerialPad(port: SerialPort)`。`SerialPort` 是同一个文件里的 `typing.Protocol`，只要 `write(data: bytes) -> int | None`、`read(size: int) -> bytes`、`reset_input_buffer() -> None`、`close() -> None`。`serial.Serial` 符合它，测试里的假串口也符合它。
- 函数 `open_serial_pad(settings) -> SerialPad`：
  1. `settings.serial_port` 是 `None` 时抛 `ValueError`，报错里写 `CONTROLLER=serial 时要在 .env 里写 SERIAL_PORT`。
  2. 用 `serial.Serial(settings.serial_port, settings.serial_baud, timeout=0.5)` 打开。打不开（`serial.SerialException`，或者 `OSError`）抛 `DeviceCheckError`，报错是 `按键：串口 {port} 打不开：{原来的报错}`。
  3. 清掉输入缓冲，握手：发 `A5 A5 81`，读 1 个字节，要是 `80`。
  4. 停脚本：发 `A5 84`，读 1 个字节，要是 `83`。
  5. 3、4 任何一步读不到字节（超时返回空）或者读到的不对，关掉串口，抛 `DeviceCheckError`，报错是 `按键：单片机没有回应（{哪一步}，收到 {十六进制或「空」}）`，提示检查 TTL 的接线和波特率。
- `serial_pad.py` 用 `import serial`，测试里替换 `control_switch.device.serial_pad.serial.Serial`。
- 按键名到按钮位、HAT 的对照写在 `serial_pad.py` 里，按键名和 botbase 的一样：`A`、`B`、`X`、`Y`、`L`、`R`、`ZL`、`ZR`、`PLUS`、`MINUS`、`LSTICK`、`RSTICK`、`HOME`、`CAPTURE`、`DUP`、`DDOWN`、`DLEFT`、`DRIGHT`。不认识的按键名抛 `ValueError`，报错里写出按键名。
- `click(button, delay=0.15)`：发按下的报文，等 `PRESS_TIME`（模块常量 0.1 秒），发中立报文，再等 `delay`。
- `stick(side, x, y, hold)`：`side` 是 `LEFT` 或 `RIGHT`，别的值抛 `ValueError`。`x`、`y` 按 botbase 的范围换算成 0–255：`round(128 + v * 127 / 0x7FFF)`，y 要反过来（y 正数向上 → 轴值变小），结果限制在 0–255。发推摇杆的报文，等 `hold`，发中立报文。
- 每发一个报文读 1 个字节：`FF` 正常；读不到或不是 `FF` 抛 `ConnectionError`，报错里写收到了什么（`FE` 写明是单片机在跑脚本）。
- 两次报文之间不到 30 ms 时先等够（用 `time.monotonic()`、`time.sleep()`，测试会替换 `time` 模块上的这两个函数）。
- `close()`：先发一次中立报文（出错不管），再关串口；调用多次不出错。

### `device/factory.py`

- `controller` 是 `serial` 时调 `open_serial_pad(settings)`，不再抛 `NotImplementedError`。`factory.py` 用 `from .serial_pad import open_serial_pad` 引用；测试里替换 `control_switch.device.factory.open_serial_pad`。
- 先检查完还没实现的（`SCREEN=capture`），有就抛 `NotImplementedError`，不打开串口、不连 botbase。
- 先打开单片机，再连 botbase：串口没配或打不开时不用去连 botbase。连 botbase 失败时，先把已经打开的单片机关掉再抛错。
- 三项都不用 botbase 时不连 botbase（现在只有 `CONTROLLER=serial` 时 `SCREEN` 只能是 botbase，所以这一条要等采集卡做了才会碰到）。

### `device/check.py`

- 按键：单片机能不能用，在 `open_serial_pad` 握手时就确认了，`check_devices` 里不再单独检查，和 botbase 一样。
