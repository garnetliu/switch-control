# 重构：任务总览

## 目标

- 所有代码收进一个包 `src/control_switch/`，加上 `tests/`。
- 取图、按键、读写内存拆成三个接口，用哪种硬件由 `.env` 决定，可以随意组合。
- 脚本只声明自己需要哪些能力，启动时统一检查设备。

重构期间不改任何游戏逻辑：坐标、阈值、步骤、打分都不动。

`src/swsh/lair/` 下现在有没提交的改动，要先提交。任务 02 起会移动这些文件。

## 三个角色

每个任务按顺序过三个角色，前一个做完下一个才开始。

| 角色 | 做什么 | 能改什么 |
|---|---|---|
| 写测试 | 按任务文件里「写测试」一节写测试。这时实现还没做，测试跑不过是正常的 | 只能改 `tests/` |
| 实现 | 按「实现」一节改代码，改到测试全部通过 | 不能改 `tests/` |
| 测试 | 站在使用者的角度检查这个任务有没有做完、做对、写法好不好。任务文件「测试」一节是最低要求，之外还要自己找问题 | 只能改 `tests/` |

- 每个角色只拿到当前这一个任务的文件，看不到其他任务和这份总览。
- 实现的人觉得测试写错了，不自己改，写明哪一条、为什么，退回给写测试的人。
- 测试的人找到的问题，确认是真的问题的，每个写一条能复现它的测试用例放进 `tests/`，然后退回给实现的人。这条用例留在项目里，以后的改动再出同样的问题会被它拦住。
- 测试的人不改实现代码，发现问题也不自己修。
- 写法好不好，对照 `.claude/skills/` 下的规范：`python-best-practices`、`design-patterns`、`architecture`、`testing-tdd`、`type-safety`、`error-handling`。
- 用到某个库的接口之前，先在项目已安装的版本里确认（看 `.venv` 里的源码，或者实际调用一次），不凭记忆写。OpenCV、rapidocr、pyusb、pyserial、pytest、hatchling 这些库没有现成的规范可以对照。
- 从重构前原样移动过来的代码也要完整地测，和新写的代码一个标准。里面原来就有的问题同样写测试用例、同样退回给实现的人修。
- 任务 02 到 04 写的「只移动文件、逻辑不动」指的是第一遍实现。测试找到问题退回之后，实现的人可以改逻辑，只改到对应的测试用例通过为止；改动了游戏逻辑的要单独列出来，由人在真机上确认。
- 三个角色都不提交。任务通过、真机确认之后由人来提交。

## 每个角色跑一次

每个角色只跑一次，不做多次对比。

后面的环节发现任务文件写错或漏了，停下来，回去改任务文件，不让角色自己绕过去。

### 用清单找漏的

下面的清单用命令列出来，不靠模型判断，每一项都要有着落。

写测试做完之后：

| 清单 | 怎么列出来 | 每一项要对上什么 |
|---|---|---|
| 任务文件「写测试」一节的每一条 | 从任务文件里按行取 | 至少一条测试用例 |
| 这个任务移动或新建的模块里，每个对外的函数、类、方法 | 用命令从源文件里解析出来 | 有测试用例用到它，或者写明为什么不测 |

测试做完之后：

| 清单 | 怎么列出来 | 每一项要对上什么 |
|---|---|---|
| 任务文件「测试」一节的每个编号 | 从任务文件里按行取 | 有实际运行的结果 |
| 任务文件「约定」一节的每一条 | 从任务文件里按行取 | 有人核对过，写了是否照做 |
| 这个任务改动的每个文件 | `git status`、`git diff --name-only` | 在范围内，并且有人看过 |
| 这个任务改动的每一行代码 | 测试覆盖率报告里没被任何测试跑到的行 | 补一条测试用例，或者写明为什么跑不到 |

对不上的每一项，退回给对应的角色补；判断不了是不是漏的，交给人。

每个任务的清单结果存在 `docs/重构/记录/` 下，一个任务一个文件。

## 类型检查怎么算通过

- 类型检查用 pyright 的标准模式（`standard`），不用严格模式。
- 每个任务做完，`make typecheck` 都要 0 报错，范围是 `src/control_switch/` 和 `tests/`。
- 搬进来的旧代码原来就有的类型报错，由搬它的那个任务清掉。可以用的办法只有这几种：补类型标注；给变量赋初值；加 `assert` 判空；用 `typing.cast`。
- 不用 `# type: ignore` 和 `# pyright: ignore` 把报错压掉。第三方库没有类型信息造成的报错确实绕不开时可以用，要在同一行写明原因。
- 这些改动都不能改变正常运行时的结果。
- 核对搬过去的文件内容有没有变时，允许的改动是：import；上面这几种为清类型报错做的改动；这个任务「实现」里明确写了的其他改动。
